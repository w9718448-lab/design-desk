## 1. 它是什么

## 2. 协作约定（必须遵守）

**关于她**
- 非程序员，Mac 为主，也可能用 Windows。手头紧，优先免费方案。
- 要结论在前、简短的中文；需要她动手时给“点哪里、填什么”的步骤。
- 每轮做完给她**预览（截图或可点的页面）**，她确认后再定稿。

**安全与数据（她的原话要求）**
- 私人工作数据只在本机导入，**不发给外部模型、不提交 GitHub**。先备份已有数据，**不要无提示覆盖**现有工作台。
- GitHub 登录由她自己在官方页面完成：**不向她要密码、令牌或 API Key，不读取或打印系统钥匙串**。
- 不代发飞书或其他外部消息。
- 只有会改变核心方向、产生付费、覆盖数据或对外发布时，才集中列出选项让她选。

**她已定下的产品偏好**
- 需求一开始是模糊的：每项有“已确定 / 大致 / 待确定”三种状态；需求卡只摆有内容的项，待确定的收起。
- 设计台**不负责拟话术**（不做追问草稿）。
- 资产库是她自己的仓库（自己产出 + 收集的图和源文件）：只留**搜索 + 拖拽上传 + 文件夹**；AI 关键词**隐藏**，只用于检索。
- 评审不通过也能“就用这一版，提交终稿”；交付完成后终稿自动进资产库“我的作品”。
- 品牌规则她暂时没有，保持空框架（感觉 / 原则 / 指引三层）。
- 界面操作尽量用**图标按钮**（带悬停说明）；历史项目要**紧凑**。
- 设置统一在左栏底部：外观（深浅色）+ 模型密钥 / 评审角色 / 品牌规则。
- 删除项目 = 先进“历史项目 · 已删除”，可恢复或彻底删除。

## 3. 现在的功能（v0.4.0）

| 步骤 | 做什么 |
|---|---|
| 需求 | 写一段背景建项目；随时“补充项目背景”自动识别并合并（不覆盖已确定项）；需求卡 12 项可改；拖入固定参考（Logo 等） |
| 创意发散 | 从需求词生成脑图；单击发散、双击放大居中、☆ 收藏进“创意组合” |
| 视觉风格 | 按创意组合或自己输入的词，从资产库匹配图片；选用后可框选重点、写备注 |
| 出稿 | 设计卡片（需求 + 关键词 + 固定/风格/资产库参考图 + 提示词），可复制或下载 PNG；方向说明、生图提示词；拖入稿件或从资产库放入 |
| 评审 | 五个可编辑角色（品牌/受众/拍板人/制作/文案）挑问题；有千问 Key 时自动看图，否则生成检查清单；问题可转成品牌规则 |
| 交付 | 选终稿、交付核对、建议文件名、复盘；完成后终稿进资产库 |

其他：首页项目看板、资产库、历史项目（已完成 / 已删除）、设置。
没有配置模型时全部走本地规则；配上**通义千问**（qwen-plus 文字、qwen-vl-max 看图，DeepSeek 作文字备用）才是真正的 AI 发散与看图评审。

## 4. 技术结构

- **技术栈**：Next.js 16（webpack 构建，`output: "standalone"`）+ React 19 server actions，TypeScript，无数据库，无 UI 库，纯 CSS（`src/app/globals.css`，CSS 变量做深浅两套皮肤）。
- **目录**
  - `src/app/actions.ts`：所有写操作（server actions），每个都是 `export async function xxx(form: FormData)`。
  - `src/app/**/page.tsx`：页面（服务端组件）。`src/app/briefs/[id]/[step]/page.tsx` 是六步的统一外壳。
  - `src/components/steps/*`：六步各自的界面；`mind-map.tsx` 脑图；`design-card.tsx` 设计卡片（Canvas 画 PNG）；`dropzone.tsx` 拖拽上传；`icons.tsx` 图标（线性 SVG 路径表）。
  - `src/lib/types.ts`：数据结构（Brief、Asset、Draft、Review、Rule、Role、Folder 等）和需求字段、步骤定义。
  - `src/lib/store.ts`：数据读写。单个 JSON 文件 `design-desk.json`，**原子写入 + .bak 备份 + 写队列**；`migrate()` 负责旧版数据升级，升级前另存 `design-desk.v{N}.backup.json`。
  - `src/lib/brief.ts` 需求识别；`ideas.ts` 脑图；`assets.ts` 资产打标签与检索；`review.ts` 评审；`direction.ts` 方向说明与提示词；`ai.ts` 模型接口与密钥；`files.ts` 文件保存；`file-url.ts` 文件访问地址。
- **数据位置**：环境变量 `DESIGN_DESK_DATA_DIR`；安装包里由启动脚本设为 `~/Documents/设计台数据`。上传的文件在其中的 `uploads/`（稿件、固定参考）和 `assets/`（资产库）。
- **密钥**：Mac 存在钥匙串（服务名 `com.shangdengma.workbench.ai`，和她的“上等马”工作台共用）；其他系统存在数据目录的 `模型密钥.json`。代码不得打印或上传它们。
- **数据版本**：当前 `version: 3`。改数据结构时：在 `types.ts` 加可选字段，在 `normalizeBrief()` / `migrate()` 里补默认值；真要改结构就把版本号加 1，并在 `migrate()` 里写升级逻辑（先备份）。**绝不能让旧数据读不出来。**

## 5. 改动流程（照做可以避免返工）

```bash
npm install
npm run dev                     # 开发模式 http://127.0.0.1:4180（数据在 ./data）
npx tsc --noEmit                # 类型检查，必须无错误
npm run preview                 # 正式构建并运行（数据在 ./.local-data）
npm run test:flow -- local dark # 另开终端：全流程自动点一遍，截图在 tests/out/
npm run test:flow -- local light
```

- `tests/flow.cjs` 用 Playwright（`npm i -D playwright` 或设 `PLAYWRIGHT` 指向已装的包），会：上传资产、用 `tests/sample-brief.txt`（宠味食刻宠物零食品牌）建项目、拖入 Logo、脑图发散收藏、风格匹配、设计卡片复制下载、放稿件、评审、定终稿、交付、删除/恢复/彻底删除项目、看设置页。最后打印 `errors []` 才算通过。
- 想测 AI 路径：`node tests/mock-ai.cjs`（端口 4999 的假千问），启动设计台时加 `DESIGN_DESK_QWEN_BASE_URL=http://127.0.0.1:4999`，并在设置里随便填一个 Key，再跑 `npm run test:flow -- ai dark`。
- 交付给她前：深浅两套皮肤都截图检查，手机宽度（390px）看一眼不横向滚动。

**发布新版本（安装包）**
1. 改 `package.json` 里的 `version`（例如 0.4.0 → 0.5.0），提交并推到 `main`。
2. GitHub Actions（`.github/workflows/release.yml`）会自动：类型检查 → `packaging/build-package.sh` 打包（下载官方 Node 22 并校验 SHA256，含 Mac arm64/x64 和 Windows x64）→ 发布 Releases `v0.5.0`。
3. 附件文件名必须是英文（GitHub 会吞掉中文），显示名用中文（`文件#显示名`）。
4. 只想重新打当前版本：在 Actions 页面手动运行“发布安装包”。

**更新展示版**
1. `node demo/build.mjs <公开仓库 shangdengma>/design-desk`（公开仓库 `w9718448-lab/shangdengma` 只放展示版，根目录是上等马浏览版，**别动根目录的上等马文件，也别放源码和资料**）。
2. 提交推送后 GitHub Pages 自动上线。
3. 展示版的原理：用同一套页面和组件，在打包时把 `node:fs`、文件保存、模型接口、`next/navigation`、`next/link` 换成 `demo/shims/` 里的浏览器内存实现，路由走 `#/...`。示例数据在 `demo/seed/` 和 `demo/public/files/`。新加 server action 不用改展示版（`build.mjs` 自动包装）；新加用到 Node 能力的库文件，需要在 `build.mjs` 里加对应替身。

## 6. 已知的坑

- **构建后要复制静态文件**：`next build` 之后要 `cp -r .next/static .next/standalone/.next/`，否则页面能打开但按钮全都没反应（`npm run preview` 和打包脚本已经处理）。
- **一个表单多个提交按钮**（如“保存”和“交付完成”都叫 `intent`）：服务端靠被点按钮的 name/value 区分；展示版里 React 不会自动带上，`demo/build.mjs` 已补。
- **`.panel` 是 grid 布局**：里面放 `white-space: nowrap` 的长文字会把整页撑宽，要给容器 `grid-template-columns: minmax(0, 1fr)`。
- **Playwright 上传中文文件名**：要用 `{ name, mimeType, buffer }` 方式，直接给中文路径会传空。
- **sharp / @img 不打进安装包**（体积大且用不到）。
- **Mac 拦截**：新版 macOS 右键“打开”也会被拦；教她：终端输入 `bash `（带空格）再把 `启动设计台.command` 拖进去回车，或 系统设置 → 隐私与安全性 → 仍要打开。脚本首次运行会去掉整个文件夹的隔离标记。
- **Windows 部分只在 Linux 上模拟测过**，没在真 Windows 上跑过。
- **github.io 在国内**大多能打开，偶尔慢；如需更稳，可把展示版的静态文件放到她的阿里云服务器（121.196.247.142，跑着“上等马”演示）上，需要她本人操作服务器。
