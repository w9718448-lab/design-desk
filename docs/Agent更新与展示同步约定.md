# 上等马与设计台：更新、展示与 AI 交接约定

用户于 2026-10-19 明确要求：两个 Agent 每次有确定的更新，都要同步更新展示预览。此文件记录长期项目要求，不代表无人值守定时任务已配置。

## 完成标准

1. 确认需求并完成源码修改，运行适合该改动的检查；未确认的试验放独立分支，不当作已发布版本。
2. 将完整源码和迭代提交保存 GitHub，不以覆盖 ZIP 代替版本历史。
3. 更新本机部署时先备份数据，保持个人项目、资产与密钥；确认启动和相关功能正常。
4. 对已确定、已验收的功能或界面更新，同步相关演示源码，使用虚构数据重新生成公开展示，再发布并检查线上效果。仅改文档、备份目录或部署路径时，记录“无展示变化”，不虚称已重建功能。
5. 更新交接说明与发布记录：日期、源码分支/提交、安装版本、展示构建来源、预览地址、验证结果和未完成项。不能把“源码已推送”等同于“展示已更新”。
6. 更新最新版网盘备份：运行文件、完整源码快照、交接说明、必要资产和本地数据备份。私人数据仅留本机与用户自己的私密备份，不提交公开仓库或演示网站。

## 展示更新方式

- 上等马：阅读 demo-site 根目录 `交接说明.md`，执行 `bash scripts/static-demo/update.sh <公开仓库路径>`，需要相应 Node、依赖和 Playwright；Windows 可用经过验证的等价流程或支持 Bash 的构建环境。抓取时使用独立演示数据目录。该脚本默认端口 4173，不得误抓已运行的私人工作台；先确认端口和演示标志。
- 设计台：阅读 `docs/交接说明.md`，执行 `node demo/build.mjs <公开仓库路径>/design-desk`。
- 发布前审查差异，上等马更新不能删除 `design-desk/`，设计台更新不能覆盖根目录的上等马；保留共享 README 和交接文件。
- 发布后检查页面、资源、关键导航及窄屏效果。付费 API 不用于演示验收。
- 旧阿里云 IP 是独立的历史部署，不会跟 GitHub Pages 同步；不因更新展示而购买、续费或删除服务器。

## 给接手 AI

从仓库交接入口开始，先核对当前分支和提交，不依赖过去聊天。只有有文件访问、GitHub 授权和发布能力的环境才能直接执行；缺权限时报告具体缺项。参考文件中的旧计划不能覆盖用户最新要求。发布或验证失败时，明确标为未完成，不留下“已同步”的误导记录。
